# 테스트 지침

무엇을 어느 깊이로 테스트하고 언제 쓰는지를 정한다. 테스트를 쓰거나 고칠 때 읽는다.

## 기준

- 모듈이 외부에 약속한 것 하나가 테스트 하나다. 약속의 출처는 ADR의 Decision 문장, `specs/`의 사양 문장, Swagger의 제약(글자 수, enum, 상태 코드)이다.
- 구현 방식은 검증하지 않는다. 내부 상태, 호출 순서, 사용한 라이브러리의 동작은 테스트 대상이 아니다.
- 테스트 이름은 요구사항 문장으로 쓴다. 파일만 읽어도 무엇을 약속했는지 알 수 있어야 한다.
- 라이브러리 자체의 동작(TanStack Query의 캐시, React Router의 매칭)은 테스트하지 않는다.

## 레이어별 방식과 시점

| 레이어                                       | 방식                                                       | 시점                                        |
| -------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------- |
| `shared/lib`, `shared/api`, `entities/model` | 순수 함수 단위 테스트. 경계값과 실패 경로 포함             | 구현 전에 먼저 쓴다                         |
| `features`                                   | Testing Library로 사용자 행위와 보이는 결과만 검증         | 사양 문장을 구현할 때 같은 작업 안에서 쓴다 |
| `widgets`, `pages`                           | 목 API 핸들러를 붙인 통합 테스트 소수                      | 화면이 갖춰진 뒤 쓴다                       |
| `app`                                        | 초기화 루트 단위 테스트와 프로바이더, 라우터 스모크 테스트 | 초기화 구조가 바뀔 때                       |

- Jotai 아톰은 `createStore()`로 React 없이 검증한다.
- 30초 자동 저장처럼 시간이 관여하면 `vi.useFakeTimers()`를 쓴다.
- 테스트는 네트워크를 타지 않는다. API 호출은 요청 가로채기로 대체한다.

## 쿼리와 단언

- 쿼리는 `getByRole`, `getByLabelText`를 우선 쓴다. 테스트 ID는 역할로 찾을 수 없을 때만 쓴다.
- 비동기 렌더링은 `findBy*`로 기다린다. `waitFor` 안에 단언을 여러 개 넣지 않는다.
- `.resolves`, `.rejects` 단언은 반드시 `await`한다. Vitest 5는 await하지 않은 비동기 단언을 실패로 처리한다.
- `clearMocks`가 기본 true라 목 호출 기록은 테스트마다 초기화된다. 별도 `beforeEach` 정리를 쓰지 않는다.

## 파일 배치

- 테스트 파일은 대상 파일과 같은 디렉토리에 `<이름>.test.ts` 또는 `<이름>.test.tsx`로 둔다. 상세는 `docs/file-structure.md`.
- 테스트 셋업은 `src/shared/config/test-setup.ts`에 둔다.
- 여러 테스트가 공유하는 렌더 헬퍼는 `src/shared/config/` 아래에, 엔티티 픽스처는 해당 `entities/<엔티티>/model`에 둔다. 필요해질 때 만든다.
- 테스트용 인스턴스는 `initializeSystem()` 또는 개별 팩토리로 만든다. QueryClient는 `retry: false`로 만든다.

## 완료 기준

- 순수 로직 모듈은 export된 함수의 약속마다 테스트가 있다.
- `features` 슬라이스는 사양 문장 수와 테스트 수가 같다.
- `it.skip`, `it.todo`가 남아 있으면 완료가 아니다.
- 커밋은 초록 상태로만 한다. 작업 트리에서는 빨간 테스트를 먼저 쓰되, 커밋 단위는 테스트와 구현이 함께 든 하나다.
