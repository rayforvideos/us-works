`shared/ui` 컴포넌트 하나를 ADR-0007, ADR-0009의 규칙으로 진행한다. 대상: $ARGUMENTS

체크포인트는 착수, 커밋 전, 합병 세 곳이다. 각 체크포인트에서는 보고만 하고 사용자의 답을 기다린다. 답을 받기 전에 다음 단계를 시작하지 않는다.

1. 이슈를 만든다. 라벨 `feat`, 본문에 속성 목록, 변형 표(속성 × 값 → 배경, 글자, 테두리, 치수), 상태 색, 작업 목록. 스펙 문서는 쓰지 않는다.
2. 변형 표는 Figma에서 읽은 값으로만 채운다. Figma에 없는 상태 색은 인접 팔레트 단계 규칙으로 제안하고 `[확인 필요]`로 표시한다.
3. 체크포인트 착수. 변형 표, 작업 목록, `[확인 필요]`를 보고하고 답을 이슈에 반영한다.
4. `main`에서 `<이슈번호>-<짧은-영문-설명>` 브랜치를 만든다.
5. 구현한다. `shared/ui/<이름>/{<이름>.tsx, <이름>.test.tsx, index.ts}`, 변형은 `cva()`, 병합은 `cn(variants(props), className)`, 색과 크기는 `@theme` 토큰만 쓴다. Figma에 없는 조합은 타입으로 막는다. 상호작용 상태는 CSS 상태로 표현한다.
6. 변형 하나마다 테스트 한 문장을 쓴다. 역할, 이름, 상태로 요소를 찾고 클래스 문자열은 검사하지 않는다. `pnpm check`를 통과시킨다.
7. 체크포인트 커밋 전. 변경 파일, 검증 방법, 커밋 분할과 메시지를 보고한 뒤 `AskUserQuestion`(header `🔒 체크포인트`, 선택지 `승인`/`수정 필요`, 첫 줄에 "커밋 전 체크포인트"와 실행될 명령)을 띄운다. 사용자가 `승인`을 고르기 전에는 커밋하지 않는다. `수정 필요`나 자유 입력이면 요청을 반영하고 6번으로 돌아간다.
8. 토큰이 생기면 승인받은 분할대로 커밋하고, 푸시하고, PR을 만든다. PR 본문 첫 줄 `Closes #<이슈번호>`, 화면 항목에 변형별 캡처 또는 확인 방법, 완료 체크리스트를 채운다. PR 생성에서 토큰이 닫힌다.
9. CI 결과를 보고한다. 체크포인트 합병. 같은 체크포인트 질문에서 사용자가 다시 `승인`을 고르면 merge commit으로 합친다.
