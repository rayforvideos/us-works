화면 단위 기능 하나를 ADR-0008의 흐름으로 진행한다. 대상: $ARGUMENTS

체크포인트는 착수, 커밋 전, 합병 세 곳이다. 각 체크포인트에서는 보고만 하고 사용자의 답을 기다린다. 답을 받기 전에 다음 단계를 시작하지 않는다.

1. 이슈를 만든다. 라벨 `feat`, 본문에 대상 화면, 엔드포인트, 스펙 링크 자리, 슬라이스 단위 작업 목록.
2. `specs/TEMPLATE.md` 형식으로 `specs/<이슈번호>-<이름>.md` 초안을 쓴다. Swagger에서 엔드포인트 요청과 응답을 확인하고, 확신이 없는 곳은 `[확인 필요]`로 남긴다.
3. 체크포인트 착수. 작업 목록과 `[확인 필요]` 목록을 보고한다. 답을 스펙에 반영하고 `[확인 필요]`를 모두 지운다. 남아 있으면 구현을 시작하지 않는다.
4. `main`에서 `<이슈번호>-<짧은-영문-설명>` 브랜치를 만든다.
5. 구현한다. 순수 로직은 `R-xx` 테스트를 먼저 쓰고, 화면 흐름은 `S-xx` 테스트를 구현하면서 쓴다. 테스트 이름은 스펙 문장 그대로다. 로딩, 빈 목록, 오류, 성공 상태를 모두 다룬다.
6. `pnpm check`를 통과시킨다.
7. 체크포인트 커밋 전. 변경 파일, 검증 방법, 커밋 분할과 메시지를 보고한 뒤 `AskUserQuestion`(header `🔒 체크포인트`, 선택지 `승인`/`수정 필요`, 첫 줄에 "커밋 전 체크포인트"와 실행될 명령)을 띄운다. 사용자가 `승인`을 고르기 전에는 커밋하지 않는다. `수정 필요`나 자유 입력이면 요청을 반영하고 6번으로 돌아간다.
8. 토큰이 생기면 승인받은 분할대로 커밋하고, 푸시하고, PR을 만든다. PR 본문 첫 줄 `Closes #<이슈번호>`, 템플릿의 완료 체크리스트를 모두 채운다. 체크하지 못하는 항목이 있으면 PR을 올리지 않는다. PR 생성에서 토큰이 닫힌다.
9. CI 결과를 보고한다. 체크포인트 합병. 같은 체크포인트 질문에서 사용자가 다시 `승인`을 고르면 merge commit으로 합친다.
