# 26 회원가입

## API

- `POST /api/v1/auth/register`: 이메일과 비밀번호로 계정을 만들고 세션을 발급받는다. 201이면 토큰과 사용자, 409면 이메일 중복, 400이면 형식 오류.

## 범위 밖

- 비밀번호 확인 입력, 약관 동의, 이메일 인증(Figma와 API에 없다)
- 토큰 만료 확인과 갱신(`shared/api`가 처리한다, ADR-0006)

## 데이터와 제약

| 필드     | API 필드   | 제약              | 문구                                                            |
| -------- | ---------- | ----------------- | --------------------------------------------------------------- |
| 이메일   | `email`    | 필수, 이메일 형식 | "이메일을 입력해주세요.", "이메일 형식이 올바르지 않습니다."    |
| 비밀번호 | `password` | 필수, 6자 이상    | "비밀번호를 입력해주세요.", "비밀번호는 6자 이상이어야 합니다." |

## 화면 상태

- 기본: 로고와 제목, 이메일·비밀번호 필드, 회원가입 버튼, "이미 계정이 있으신가요? 로그인" 링크.
- 제출 중: 버튼이 로딩 상태이고 입력이 비활성이다.
- 필드 오류: 해당 필드 아래에 문구가 보이고 요청을 보내지 않는다.
- 요청 오류: 버튼 위에 문구가 보이고 입력값은 유지된다.
- 성공: 응답의 토큰으로 세션을 저장하고 `/`로 이동한다. 별도 로그인은 없다.

## 규칙

- R-01 이메일이 비어 있으면 "이메일을 입력해주세요." 오류다
- R-02 이메일이 형식에 맞지 않으면 "이메일 형식이 올바르지 않습니다." 오류다
- R-03 비밀번호가 비어 있으면 "비밀번호를 입력해주세요." 오류다
- R-04 비밀번호가 6자 미만이면 "비밀번호는 6자 이상이어야 합니다." 오류다
- R-05 회원가입 응답의 `kind`가 `conflict`면 "이미 가입된 이메일입니다."를 보인다
- R-06 회원가입 응답의 `kind`가 `network`면 "네트워크 연결을 확인해주세요."를, `server`면 "잠시 후 다시 시도해주세요."를 보인다

## 흐름

- S-01 Given 빈 폼 When 회원가입을 누르면 Then 두 필드 아래 필수 오류가 보이고 요청을 보내지 않는다
- S-02 Given 유효한 값 When 회원가입을 누르면 Then 버튼이 로딩 상태가 되고 입력이 비활성이 된다
- S-03 Given 유효한 값 When 서버가 201로 응답하면 Then 세션이 저장되고 `/`로 이동한다
- S-04 Given 유효한 값 When 서버가 409로 응답하면 Then "이미 가입된 이메일입니다."가 보이고 입력값은 유지된다
- S-05 Given 회원가입 페이지 When "로그인" 링크를 누르면 Then `/login`으로 이동한다
- S-06 Given 세션이 있는 상태 When `/register`에 접근하면 Then `/`로 이동한다
