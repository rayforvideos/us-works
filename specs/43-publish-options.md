# 43 발행 옵션 모달

## API

- `POST /api/v1/contents`, `PUT /api/v1/contents/{id}`: 모달의 발행하기가 먼저 콘텐츠를 저장한다.
- `PATCH /api/v1/contents/{id}/status`: `public`이면 공개(예약은 서버가 지운다), `private`이면 비공개.
- `POST /api/v1/contents/{id}/schedule`: 예약 등록. `PUT`: 예약 시각 변경. `DELETE`: 예약 삭제(비공개로 바꾸기 전에 호출). 한 번 공개된 콘텐츠는 400.
- `GET /api/v1/contents/{id}/notification`: 수정 화면의 알림 초기값.
- `POST /api/v1/notifications`: 알림 생성. 예약 발행이면 `scheduled_at`에 예약 시각, 공개면 생략(즉시 발송).
- `PUT /api/v1/notifications/{id}`, `PUT .../schedule`, `DELETE /api/v1/notifications/{id}`: 기존 알림 수정·삭제.

## 범위 밖

- 알람 목록·알람 작성 페이지의 동작(그대로 둔다)
- 브라우저 뒤로가기 시 종료 확인
- 모달 안에서의 임시저장(모달을 닫으면 작성 페이지의 임시저장 동작이 그대로 이어진다)

## 화면 상태

- 열기: 모달 제목은 "발행하기"이고 하단에 취소·발행하기 버튼이 있다. 작성·수정 페이지의 발행하기를 누르면 폼 검증(제목·내용·카테고리)을 먼저 통과해야 열린다. 폼 검증에 실패하면 모달이 열리지 않는다. 작성이면 공개·발송·전체·콘텐츠 제목 사용 해제가 기본이다. 수정이면 콘텐츠의 현재 상태(공개/비공개/예약과 예약 시각)와 기존 알림(발송 여부·대상자·제목)으로 채운다.
- 공개 여부에 따라: 예약 발행이면 예약 시각 필드가 보이고, 비공개면 알람 설정이 비활성(미발송 고정)이다. 발송이면 대상자와 알람 내용이 보이고, 미발송이면 숨긴다.
- 예약 시각: 필드 하나. 값이 있으면 `yyyy년 MM월 dd일 HH시 mm분`, 없으면 placeholder. 필드를 누르면 브라우저 기본 날짜·시간 선택기가 열리고 분 단위로 고른다.
- 검증 오류: 필드 아래 문구가 보이고 필드가 오류 상태가 된다. 레이아웃은 밀리지 않는다.
- 이미 발송된(`sent`) 알림이 있는 콘텐츠: 알람 설정의 발송 여부·대상자·알람 내용을 기존 값으로 보이되 모두 비활성이고 "이미 발송된 알림입니다."를 보인다.
- 제출 중: 발행하기 버튼 로딩, 입력 비활성, 배경 클릭으로 닫히지 않는다.
- 요청 순서: 콘텐츠 저장 → 저장된 콘텐츠 다시 읽기(저장 전부터 콘텐츠 id가 있었으면 기존 알림도 함께 읽는다) → 공개 상태(비공개로 바꿀 때 예약이 있으면 예약 삭제 먼저) → 예약 등록·변경 → 알림 생성·수정·삭제. 중간에 실패하면 모달 위에 오류 문구를 보이고 값은 유지한다. 이미 저장된 콘텐츠는 다시 시도할 때 `PUT`으로 저장한다.
- 성공: 임시저장을 지우고 `/`로 이동한다.
- 취소·닫기·Esc: 모달만 닫히고 작성 페이지 값은 유지된다.

## 규칙

- R-01 예약 발행인데 예약 시각이 비어 있으면 "필수 정보입니다." 오류다
- R-02 예약 시각이 현재 이전이면 "시간을 다시 선택해주세요." 오류다
- R-03 발송인데 알람 내용이 비어 있으면 "알람 내용을 입력해주세요." 오류다
- R-04 비공개를 고르면 발송 여부는 미발송이 되고 바꿀 수 없다
- R-05 콘텐츠 제목 사용을 체크하면 알람 내용이 콘텐츠 제목이 되고, 해제하면 빈 값이 된다
- R-06 `publish_status`가 `scheduled`가 아니면서 `published_at`이 있는 콘텐츠(한 번 공개된 콘텐츠)는 예약 발행을 고를 수 없다
- R-07 초기값은 콘텐츠 상태에서 정한다: `publish_status`가 `scheduled`면 예약 발행과 그 시각, `status`가 `public`이면 공개, 그 외는 비공개. 알림이 있으면 발송과 그 대상자·제목, 없으면 미발송
- R-08 요청 계획은 목표 상태와 현재 상태의 차이로만 만들어서, 공개면 `PATCH public`, 비공개면 예약이 있을 때 `DELETE schedule` 뒤 `PATCH private`·없을 때 `PATCH private`, 예약 발행이면 예약이 없을 때 `POST schedule`·시각이 바뀌었을 때 `PUT schedule`이고, 목표가 현재와 같으면 아무 요청도 만들지 않는다
- R-09 알림은 발송이고 없으면 `POST`(예약이면 `scheduled_at` 포함), 발송이고 있으면 바뀐 부분만 `PUT`, 미발송이고 있으면 `DELETE`를 보낸다
- R-10 알림이 발송 완료(`sent`)면 어떤 요청도 보내지 않고, 공개로 바꿀 때는 기존 알림의 예약 시각을 그대로 둔다(알림 예약을 지우는 API가 없다)

## 흐름

- S-01 Given 작성 페이지의 유효한 폼 When 발행하기를 누르면 Then 발행 옵션 모달이 공개·발송·전체 기본값으로 열린다
- S-02 Given 모달에서 비공개를 고르면 When 알람 설정을 보면 Then 발송 여부가 미발송으로 비활성이고 대상자·알람 내용이 없다
- S-03 Given 예약 발행을 고른 모달 When 시각을 비운 채 발행하기를 누르면 Then "필수 정보입니다."가 보이고 요청을 보내지 않는다
- S-04 Given 발송을 고른 모달 When 알람 내용을 비운 채 발행하기를 누르면 Then "알람 내용을 입력해주세요."가 보이고 요청을 보내지 않는다
- S-05 Given 발송을 고른 모달 When 콘텐츠 제목 사용을 체크하면 Then 알람 내용에 콘텐츠 제목이 채워지고 입력이 비활성이 된다
- S-06 Given 작성 폼에서 공개·발송 When 발행하기를 누르면 Then `POST /contents` → `PATCH status public` → `POST /notifications`(`scheduled_at` 없음) 순으로 보내고 `/`로 이동한다
- S-07 Given 작성 폼에서 예약 발행 2027-04-05 14:30·발송 When 발행하기를 누르면 Then `POST /contents` → `POST /contents/{id}/schedule` → `POST /notifications`(`scheduled_at` 2027-04-05T14:30:00+09:00)를 보낸다
- S-08 Given 작성 폼에서 비공개 When 발행하기를 누르면 Then `POST /contents` 뒤 상태·알림 요청 없이 `/`로 이동한다
- S-09 Given 예약된 콘텐츠의 수정 화면 When 모달을 열면 Then 예약 발행과 예약 시각, 기존 알림 값이 채워져 있다
- S-10 Given 예약된 콘텐츠 When 비공개로 바꿔 발행하면 Then `PUT /contents/{id}` → `DELETE schedule` → `PATCH private` → 기존 알림 `DELETE`를 보낸다
- S-11 Given 한 번 공개된 콘텐츠의 수정 화면 When 모달을 열면 Then 예약 발행이 비활성이다
- S-12 Given 상태 변경이 400으로 실패하면 When 발행하기 뒤 Then 모달에 오류 문구가 보이고 값이 유지된다
- S-13 Given 모달 When 취소를 누르면 Then 모달이 닫히고 작성 페이지 값은 유지된다
- S-14 Given 콘텐츠 목록의 비공개 콘텐츠 행 When 보면 Then "푸시알림 생성" 버튼이 없다
- S-15 Given 작성 페이지의 빈 폼 When 발행하기를 누르면 Then 모달이 열리지 않고 폼 오류가 보인다
