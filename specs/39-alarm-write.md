# 39 알람 작성·수정

## API

- `POST /api/v1/notifications`: 콘텐츠에 알림을 만든다. `content_id`, `title`, `target_type`, `scheduled_at`. 성공 201. 콘텐츠에 이미 알림이 있으면 409.
- `GET /api/v1/notifications/{id}`: 수정 화면의 초기값. 없으면 404.
- `GET /api/v1/contents/{id}`: 작성 화면에서 콘텐츠의 발행 상태 확인. 비공개(`draft`) 콘텐츠에는 서버가 알림 생성을 400으로 거절한다.
- `PUT /api/v1/notifications/{id}`: 제목과 대상자를 수정한다. 성공 200.
- `PUT /api/v1/notifications/{id}/schedule`: 발송 시각을 수정한다. 성공 200.

## 범위 밖

- 알림 삭제(API는 있지만 Figma에 UI가 없다)
- 즉시 발송(`scheduled_at` 생략). 시간은 필수라 항상 예약 발송이다.
- 발행 옵션 모달의 푸시알림 설정(다음 기능)
- 브라우저 뒤로가기·새로고침 시 작성 종료 확인(노트는 GNB 뒤로가기만 말한다)

## 데이터와 제약

| 필드   | API 필드       | 제약                                                              | 문구                                                             |
| ------ | -------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------- |
| 콘텐츠 | `content_id`   | 작성은 `?contentId=`에서, 수정은 알림 값에서. 수정 시 보내지 않음 | -                                                                |
| 대상자 | `target_type`  | `all`, `follower`, `member` 중 하나. 기본 `all`                   | 전체, 팔로워, 멤버십                                             |
| 제목   | `title`        | 필수, 50자 이하. 우측에 `현재/50`                                 | 비면 "필수 정보입니다."                                          |
| 시간   | `scheduled_at` | 필수, 현재 이후. 타임존 포함 ISO 8601(`+09:00`)                   | 비면 "필수 정보입니다.", 과거면 "현재 이후 시간을 선택해주세요." |

## 화면 상태

- 작성(`/alarms/new?contentId=`): 대상자 전체가 선택된 빈 폼. `contentId`가 없거나 숫자가 아니면 `/`로 이동한다. 콘텐츠를 불러오는 동안 폼 자리에 스피너. 콘텐츠가 비공개(`draft`)면 폼 대신 "비공개 콘텐츠에는 알림을 보낼 수 없습니다. 콘텐츠를 먼저 공개하거나 예약해주세요."와 "목록으로" 링크를 보이고 발송하기 버튼이 없다.
- 수정(`/alarms/:id`): 불러오는 동안 폼 자리에 스피너. 실패하면 오류 문구와 "목록으로" 링크. 성공하면 값이 채워진 폼. 발송 상태가 `pending`이 아니면 입력이 비활성이고 발송하기 버튼이 없으며 "이미 발송된 알림입니다."를 보인다.
- 시간: 필드 하나. 값이 없으면 placeholder, 있으면 `yyyy년 MM월 dd일 HH시 mm분`으로 보인다. 필드를 누르면 브라우저 기본 날짜·시간 선택기(`input type="datetime-local"`)가 열리고 분 단위로 고른다.
- 검증 오류: 라벨 우측에 문구, 필드 테두리가 빨간색. 레이아웃은 밀리지 않는다.
- 제출 중: 발송하기 버튼이 로딩 상태이고 입력이 비활성이다.
- 요청 오류: 폼 위에 오류 문구가 보이고 입력값은 유지된다. 409면 "이미 알림이 있는 콘텐츠입니다.", 그 외 400은 "입력값을 확인해주세요."
- 성공: `/alarms`로 이동한다.
- 뒤로가기(화살표·제목): 입력이 바뀐 상태면 "작성을 종료하시겠습니까?" 모달. 네면 `/alarms`로 이동, 아니오나 닫기면 폼에 남는다. 바뀐 게 없으면 바로 이동한다.

## 규칙

- R-01 제목이 비어 있으면 "필수 정보입니다." 오류다
- R-02 제목은 50자까지만 입력된다
- R-03 시간이 비어 있으면 "필수 정보입니다." 오류다
- R-04 시간이 현재 이전이면 "현재 이후 시간을 선택해주세요." 오류다
- R-05 요청의 `scheduled_at`은 선택한 날짜·시간을 `+09:00` 오프셋의 ISO 8601로 만든다
- R-06 `?contentId=`가 없거나 양의 정수가 아니면 작성 화면에 들어갈 수 없다
- R-07 수정 요청은 제목·대상자가 바뀌었을 때만 `PUT /notifications/{id}`를, 시간이 바뀌었을 때만 `PUT /notifications/{id}/schedule`을 보낸다
- R-08 콘텐츠의 `publish_status`가 `draft`면 알림을 만들 수 없다

## 흐름

- S-01 Given 빈 작성 폼 When 발송하기를 누르면 Then 제목과 시간에 "필수 정보입니다."가 보이고 요청을 보내지 않는다
- S-02 Given 빈 시간 필드 When 선택기에서 2027-04-05 14:35를 고르면 Then 필드에 "2027년 04월 05일 14시 35분"이 보인다
- S-03 Given 유효한 작성 폼(`?contentId=147`) When 발송하기를 누르면 Then `POST /api/v1/notifications`에 `content_id` 147을 보내고 성공하면 `/alarms`로 이동한다
- S-04 Given 서버가 409로 응답하면 When 발송하기 뒤 Then "이미 알림이 있는 콘텐츠입니다."가 보이고 입력값은 유지된다
- S-05 Given `/alarms/12` When 페이지가 열리면 Then `GET /api/v1/notifications/12` 값으로 폼이 채워진다
- S-06 Given 발송 상태가 `sent`인 알림의 수정 화면 When 열리면 Then 입력이 비활성이고 발송하기 버튼이 없다
- S-07 Given 제목만 바꾼 수정 폼 When 발송하기를 누르면 Then `PUT /api/v1/notifications/12`만 보내고 성공하면 `/alarms`로 이동한다
- S-08 Given 시간만 바꾼 수정 폼 When 발송하기를 누르면 Then `PUT /api/v1/notifications/12/schedule`만 보낸다
- S-09 Given 입력이 바뀐 폼 When 뒤로가기를 누르면 Then "작성을 종료하시겠습니까?" 모달이 보이고, 네를 누르면 `/alarms`로 이동한다
- S-10 Given 입력이 바뀐 폼의 종료 확인 모달 When 아니오를 누르면 Then 모달이 닫히고 입력값이 유지된다
- S-11 Given 바뀐 게 없는 폼 When 뒤로가기를 누르면 Then 모달 없이 `/alarms`로 이동한다
- S-12 Given `/alarms/new`(contentId 없음) When 페이지가 열리면 Then `/`로 이동한다
- S-13 Given 비공개 콘텐츠의 `/alarms/new?contentId=147` When 페이지가 열리면 Then 폼 대신 비공개 안내와 "목록으로" 링크가 보인다
