# 35 콘텐츠 작성·수정

## API

- `POST /api/v1/contents`: 새 콘텐츠를 만든다. 성공 201.
- `PUT /api/v1/contents/{id}`: 콘텐츠를 수정한다. `link_url`이 빈 문자열이면 링크를 지운다. 성공 200.
- `GET /api/v1/contents/{id}`: 수정 화면의 초기값. 없으면 404.

## 범위 밖

- 발행 옵션 모달 안의 공개·예약·알림 설정(스펙 43). 이번 발행하기는 모달을 열고, 콘텐츠 저장은 모달의 발행하기가 한다.
- 임시저장 이어쓰기 진입(새글쓰기 모달이 담당). 이번에는 `/contents/new`에 임시저장이 있으면 그대로 불러온다.
- 서버 오류 문구의 필드별 표시(서버 문구는 영어라 쓰지 않고, 클라이언트 검증으로 먼저 막는다)

## 데이터와 제약

| 필드     | API 필드                               | 제약                                                                           | 문구                                                                     |
| -------- | -------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 카테고리 | `categories`                           | 1개 이상 3개 이하                                                              | "카테고리를 1개 이상 선택해주세요.", 3개 선택 뒤 다른 칩은 선택되지 않음 |
| 제목     | `title`                                | 필수, 50자 이하                                                                | "제목을 입력해주세요."                                                   |
| 내용     | `body`                                 | 필수, 500자 이하                                                               | "내용을 입력해주세요."                                                   |
| 링크     | `link_url`                             | 선택. `http://` 또는 `https://`로 시작하는 URL 하나. 삽입 전에는 보내지 않는다 | "올바른 링크 형식이 아닙니다."                                           |
| 임시저장 | 로컬 스토리지 `us-works.content-draft` | 제목, 내용, 카테고리, 링크, 저장 시각. 작성 화면에만                           | "해당 글이 임시 저장되었습니다 HH:mm"                                    |

## 화면 상태

- 작성(`/contents/new`): 빈 폼. 임시저장이 있으면 그 값으로 채운다. 내용이 바뀐 뒤 30초마다 자동 저장하고 헤더 임시저장 버튼은 즉시 저장한다.
- 수정(`/contents/:id`): 불러오는 동안 폼 자리에 스피너. 실패하면 오류 문구와 "목록으로" 링크. 성공하면 값이 채워진 폼. 임시저장 버튼은 보이지 않는다.
- 링크: 입력 중에는 지우기 버튼이 보이고, URL 형식일 때만 "삽입"이 활성이다. 삽입하면 아래에 링크가 표시되고 입력창은 비워진 채 비활성이 되며 "삽입된 링크가 있습니다."를 보인다. 표시된 링크의 지우기를 누르면 링크가 사라지고 입력창이 다시 활성이 된다.
- 제출 중: 발행하기 버튼이 로딩 상태이고 입력이 비활성이다.
- 요청 오류: 발행 옵션 모달에 오류 문구가 보이고 입력값은 유지된다.
- 성공: 임시저장을 지우고 `/`로 이동한다.

## 규칙

- R-01 카테고리가 0개면 "카테고리를 1개 이상 선택해주세요." 오류다
- R-02 카테고리는 3개까지만 선택할 수 있고, 3개가 선택된 뒤 다른 칩을 눌러도 선택되지 않는다
- R-03 제목이 비어 있으면 "제목을 입력해주세요." 오류다
- R-04 내용이 비어 있으면 "내용을 입력해주세요." 오류다
- R-05 링크 입력값이 `http://` 또는 `https://`로 시작하는 URL이면 삽입할 수 있고, 아니면 삽입할 수 없다
- R-06 임시저장 값은 제목, 내용, 카테고리, 링크, 저장 시각으로 저장되고, 네 필드가 모두 비어 있으면 저장하지 않는다
- R-07 요청 본문은 삽입된 링크가 있으면 `link_url`을 포함하고, 수정 화면에서 링크를 지웠으면 빈 문자열을 보낸다

## 흐름

- S-01 Given 빈 작성 폼 When 발행하기를 누르면 Then 카테고리, 제목, 내용 오류가 보이고 요청을 보내지 않는다
- S-02 Given 카테고리 3개를 선택한 상태 When 네 번째 칩을 누르면 Then 선택되지 않고 세 개가 유지된다
- S-03 Given 링크 입력에 "example" When 입력하면 Then 삽입 버튼이 비활성이고, "https://example.com"이면 활성이다
- S-04 Given 삽입 가능한 링크 When 삽입을 누르면 Then 링크가 아래에 표시되고 입력창이 비활성이 된다
- S-05 Given 삽입된 링크 When 지우기를 누르면 Then 링크가 사라지고 입력창이 활성이 된다
- S-06 Given 유효한 작성 폼 When 발행하기를 누르면 Then 발행 옵션 모달이 열리고 모달에서 발행하면 임시저장을 지우고 `/`로 이동한다
- S-07 Given 작성 폼에 입력한 상태 When 임시저장을 누르면 Then 로컬 스토리지에 저장되고 헤더에 "해당 글이 임시 저장되었습니다 HH:mm"이 보인다
- S-08 Given 작성 폼에 입력한 상태 When 30초가 지나면 Then 자동으로 임시저장된다
- S-09 Given 임시저장이 있는 상태 When `/contents/new`에 들어오면 Then 폼이 임시저장 값으로 채워진다
- S-10 Given `/contents/136` When 페이지가 열리면 Then `GET /api/v1/contents/136` 값으로 폼이 채워지고 임시저장 버튼이 없다
- S-11 Given 수정 폼 When 모달에서 발행하기를 누르면 Then `PUT /api/v1/contents/136`을 보내고 성공하면 `/`로 이동한다
- S-12 Given 서버가 400으로 응답하면 When 발행하기 뒤 Then "입력값을 확인해주세요."가 보이고 입력값은 유지된다
- S-13 Given 작성 페이지 When 뒤로가기(화살표·제목)를 누르면 Then `/`로 이동한다
