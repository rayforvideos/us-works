# ADR-0011: Keep Layouts Fluid Above Tablet Width

## Status

Accepted

## Context

Figma는 1440 데스크톱 프레임(내용 폭 1280)만 있고 태블릿·모바일 프레임이 없다. 지금 코드는 반응형 변형을 한 번도 쓰지 않아 GNB와 폼 열이 1280보다 좁은 창에서 넘친다. 모바일 대응은 범위 밖이지만, 데스크톱 창을 줄였을 때 가로 스크롤이나 겹침 없이 움직여야 한다.

## Decision

- 1280 이상은 Figma 값 그대로, 768~1279는 같은 구성을 유지한 채 유동 폭으로 줄인다. 768 미만은 보장하지 않는다.
- 브레이크포인트는 Tailwind 기본값 `xl`(1280)을 기본으로 쓰고 필요할 때만 `md`(768)를 더한다. 새 토큰은 만들지 않는다. 클래스는 작은 폭이 기본이고 Figma 데스크톱 값은 `xl:`에 둔다.
- 화면 폭을 가진 블록은 `shared/ui/container`의 공용 컨테이너(`max-w-320`, 여백 `px-9 xl:px-25`)를 쓴다.
- `shared/ui` 컴포넌트는 브레이크포인트 클래스를 쓰지 않는다. 너비는 부모가 정하며, 입력 요소는 기본 `w-full`, 버튼은 내용 크기에 `fullWidth` 옵션만 둔다. 고정 `w-*`는 아이콘과 컨트롤 크기에만 허용한다. ADR-0019가 이 항목을 대체한다.
- 반응형 판단은 위젯과 페이지가 한다. 넘치는 행은 `flex-wrap`으로 감싸고, 표는 컨테이너 안에서 가로 스크롤을 허용한다.
- 커밋 전 체크포인트에서 768과 1280 두 폭을 확인하고 PR "화면" 항목에 적는다.

## Consequences

**좋은 점**

- 창 크기가 바뀌어도 깨지지 않고, 컴포넌트는 폭 로직을 갖지 않아 단순하다.

**나쁜 점과 감수하는 위험**

- 768 미만은 검증하지 않아 모바일에서는 배치가 어긋날 수 있다. 모바일 지원이 필요해지면 이 ADR을 대체한다.
