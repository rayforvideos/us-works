# ADR-0014: Keep the Content Draft in Local Storage and Build Forms with TanStack Form and Zod

## Status

Accepted

## Context

콘텐츠 작성 페이지는 제목, 내용, 카테고리(1~3개), 링크 네 필드를 가진다. Figma 노트는 임시저장을 로컬 스토리지에 하고, 콘텐츠 하나만 임시저장하며, 작성 중 30초마다 자동 저장하고, 헤더 임시저장 버튼으로도 저장한다고 정한다. 서버에도 `publish_status=draft`(비공개) 콘텐츠를 만들 수 있어 임시저장을 서버에 둘 수도 있다. 폼은 지금까지 `useState`와 손으로 쓴 검증 함수로 만들었고, 앞으로 폼이 늘어 폼 상태와 스키마 검증 라이브러리를 정해야 한다. 이 저장소는 React Compiler를 켜 두었고 입력 컴포넌트는 모두 controlled다.

비교한 선택지는 다음과 같다(2026-09-20 기준).

- 임시저장 위치: 로컬 스토리지(노트 요구, 서버 호출 없음, 기기 간 공유 안 됨) 대 서버 비공개 콘텐츠(기기 간 공유되지만 30초마다 서버에 쓰고 목록에 미완성 글이 쌓이며 노트와 어긋남).
- 자동 저장 방식: 30초 간격 타이머(노트 요구, 최대 30초 손실) 대 입력마다 디바운스 저장(손실 적지만 노트와 다르고 저장 알림이 잦음).
- 폼 상태: react-hook-form 7.88(가장 보급됐지만 React Compiler와 충돌이 보고되고, Compiler를 일급 지원하는 v8은 beta.3 이후 정체. 입력이 모두 controlled라 `register`의 이점이 없고 `Controller`만 남는다) 대 TanStack Form 1.33(스토어 구독 방식이라 Compiler와 마찰이 없고 controlled 입력과 필드 API가 맞는다. 17 kB, v2 alpha 진행 중) 대 `useState` + 순수 검증(의존성 없이 가장 가볍지만 폼이 늘면 검증·오류·제출 상태 코드가 페이지마다 반복된다).
- 스키마 검증: zod 4.6(생태계와 문서가 가장 넓고 `zod/mini`가 있다) 대 valibot 1.5(더 작다) 대 arktype 2.2. 셋 모두 Standard Schema v1을 구현해 TanStack Form에 어댑터 없이 들어간다.

## Decision

- 임시저장은 로컬 스토리지 한 키(`us-works.content-draft`)에 둔다. 값은 제목, 내용, 카테고리, 링크, 저장 시각이며 콘텐츠 하나만 저장한다. 새 콘텐츠 작성에만 적용하고 수정 페이지에서는 저장하지 않는다.
- 작성 페이지는 내용이 바뀐 뒤 30초마다 자동 저장하고, 헤더의 임시저장 버튼은 즉시 저장한다. 저장하면 헤더 상태 문구에 "해당 글이 임시 저장되었습니다 HH:mm"을 보인다.
- 저장된 임시 콘텐츠는 새글쓰기 모달의 "임시저장된 콘텐츠 이어쓰기"가 불러오고, "새 콘텐츠 작성하기"는 지운다. 발행에 성공하면 지운다.
- 폼 상태는 TanStack Form(`@tanstack/react-form`)으로, 검증 스키마는 zod 4로 쓴다. 스키마는 기능의 `model`에 두고 구현 전에 테스트하며, 폼은 같은 스키마를 Standard Schema로 넘긴다. 로그인·회원가입 폼도 같은 방식으로 맞춘다.
- 작성과 수정은 한 페이지(`/contents/new`, `/contents/:id`)가 맡고, 수정은 `GET /contents/:id`로 채운 뒤 `PUT`, 작성은 `POST`로 보낸다.

## Consequences

**좋은 점**

- 서버 호출 없이 노트가 요구한 임시저장 동작을 만족하고, 검증 규칙이 스키마 한 곳에 모여 폼과 테스트가 같은 것을 본다. React Compiler와 충돌 없이 폼 상태를 위임한다.

**나쁜 점과 감수하는 위험**

- 임시저장은 같은 브라우저에서만 이어진다. 30초 간격이라 마지막 저장 뒤 최대 30초의 입력은 잃을 수 있으며 헤더 버튼으로 즉시 저장할 수 있으므로 감수한다.
- TanStack Form은 react-hook-form보다 보급이 적고 v2 전환이 예정되어 있어 나중에 마이그레이션 비용이 생길 수 있다. 스키마는 Standard Schema라 폼 라이브러리를 바꿔도 그대로 쓴다.
- 번들에 약 17 kB(폼)와 zod가 더해진다.
