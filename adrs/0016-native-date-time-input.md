# ADR-0016: Pick Date and Time with the Native Input

## Status

Accepted

## Context

알람 작성과 발행 옵션 모달은 예약 시각을 받는다. Figma는 필드를 누르면 달력과 30분 간격 `Time` 목록이 나란히 열리는 선택기를 그렸고, 노트는 분 단위까지 고를 수 있다고 적었다. 두 요구가 어긋나 구현이 한 번 뒤집혔다. 이슈 #39는 브라우저 기본 `datetime-local`로 만들었고, 이슈 #41에서 Figma 모양에 맞춰 Base UI Popover에 날짜 입력과 30분 목록을 담은 선택기로 바꿨다가, 이슈 #43 작업 중에 다시 기본 입력으로 되돌렸다. 되돌린 이유는 30분 제한이 Figma 노트(분 단위)와 완료 화면의 예시 값(17시 10분)과 맞지 않고, 예약 발행과 알람 발송 두 화면이 같은 컨트롤을 써야 했기 때문이다.

비교한 선택지는 다음과 같다.

- 브라우저 기본 `input type="datetime-local"`: 의존성이 없고 키보드·모바일·접근성을 브라우저가 맡는다. 선택기 모양이 브라우저마다 달라 Figma와 같지 않고, `step`으로 분 단위를 제한해도 Safari와 Firefox는 목록을 좁히지 않는다.
- Base UI Popover에 날짜 입력과 시간 목록을 담은 자체 선택기: Figma 모양에 가깝고 목록을 우리가 통제한다. 날짜는 결국 기본 달력을 열어 팝오버가 두 겹이 되고, 목록 스크롤과 포커스, 선택 값 복원을 직접 만들어야 한다.
- 달력 라이브러리(react-day-picker 등): 모양은 가장 자유롭지만 의존성과 번들이 늘고, 이 과제에서 쓰는 화면은 두 곳뿐이다.

## Decision

- 날짜와 시각은 `shared/ui/date-time-field` 하나로 받고, 그 안은 브라우저 기본 `input type="datetime-local"`이다. 값은 `yyyy년 MM월 dd일 HH시 mm분`으로 보이고 입력은 투명하게 겹친다.
- 분은 제한하지 않는다. Figma가 그린 30분 목록은 따르지 않고, 노트가 적은 분 단위 선택을 따른다.
- 달력 UI를 직접 만들거나 달력 라이브러리를 더하지 않는다. 프리미티브 사용 범위는 ADR-0015가 정한 Select와 Dialog 그대로 두고 Popover로 넓히지 않는다.
- 서버로 보내는 값은 `shared/lib/seoul-time`이 `+09:00` 오프셋의 ISO 8601로 만든다. 예약 시각을 다루는 화면은 모두 이 필드와 변환을 쓴다.

## Consequences

**좋은 점**

- 의존성이 늘지 않고, 키보드 조작과 모바일 입력을 브라우저가 맡는다. 예약 발행과 알람 발송이 같은 컨트롤과 같은 변환을 쓴다.

**나쁜 점과 감수하는 위험**

- 선택기 모양이 브라우저마다 다르고 Figma의 달력·시간 목록과 같지 않다. 값의 표시 형식은 우리가 그리므로 필드 자체는 화면마다 같다.
- 분 단위를 열어 두어 사용자가 17시 10분 같은 값을 고를 수 있다. 서버가 막지 않으므로 그대로 저장된다.
- 다시 볼 조건: 디자인이 30분 단위를 요구로 확정하거나, 예약 시각을 다루는 화면이 셋 이상으로 늘어 목록·달력을 우리가 통제해야 하면 자체 선택기를 다시 검토한다.
