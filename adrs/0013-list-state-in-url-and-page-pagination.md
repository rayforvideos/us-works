# ADR-0013: Keep List State in the URL and Paginate by Page Number

## Status

Accepted

## Context

콘텐츠 목록과 알람 목록은 필터(카테고리, 상태)와 페이지를 가진 표 화면이다. 목록 API는 `page`, `limit`, 필터 쿼리를 받고 `total`을 돌려준다. Figma 노트는 페이지네이션 방식을 자유롭게 정하라고 하고, 필터·페이지 상태를 어디에 둘지는 정해진 바가 없다. 새로고침과 뒤로 가기에서 같은 목록이 보여야 하고, 두 탭이 같은 방식을 써야 한다.

## Decision

- 목록의 필터와 페이지는 URL 검색 파라미터(`?page=&category=&publish_status=`)에 둔다. Jotai 아톰에 두지 않는다. 페이지가 파라미터를 읽어 정규화한 뒤 TanStack Query 키(`[엔티티, "list", params]`)로 넘기고, 필터 변경은 `page`를 지운다.
- 페이지네이션은 페이지 번호 방식이다. 서버 `total`로 페이지 수를 계산하고 이전·다음과 최대 5개 번호를 보인다. 무한 스크롤은 쓰지 않는다. 행 클릭으로 다른 화면에 갔다가 돌아올 때 위치가 URL로 복원되기 때문이다.
- 목록 페이지 상단의 로고·탭·액션 헤더는 `widgets/list-header`이며 탭 목록을 prop으로 받는다. 작성 페이지의 `widgets/gnb`와 별개의 위젯이며 두 목록 탭이 공유한다.
- 표와 필터는 그 페이지의 `ui` 세그먼트(`pages/<페이지>/ui/<엔티티>-table`)에 둔다. 한 페이지에서만 쓰는 블록은 FSD 기준으로 페이지 슬라이스에 두고, 두 페이지 이상이 쓰게 되면 그때 `widgets`로 올린다. 표 하나가 헤더, 행, 로딩·빈 목록·오류 상태를 모두 그린다. 행 단위 부가 동작(푸시알림 생성)은 행 안의 링크(버튼 모양)이며 행 클릭 이동과 이벤트가 겹치지 않게 전파를 막는다.
- 페이지 폭보다 넓어지면 표는 컨테이너 안에서 가로 스크롤한다(ADR-0011).

## Consequences

**좋은 점**

- 목록 위치가 링크로 공유·복원되고, 두 탭이 같은 파라미터 규칙과 위젯을 쓴다.

**나쁜 점과 감수하는 위험**

- 파라미터 정규화 코드가 페이지마다 필요하다. 엔티티 `model`의 순수 함수로 두고 테스트로 묶는다.
