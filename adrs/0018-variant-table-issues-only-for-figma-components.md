# ADR-0018: Require Variant Table Issues Only for Figma Component Sets

## Status

Accepted

## Context

ADR-0009는 `shared/ui` 컴포넌트마다 변형 표를 담은 이슈를 요구한다. 그 요구는 Figma 컴포넌트 페이지의 다섯 묶음(Button, Label, Control, Input box, GNB)처럼 속성 × 값 표가 이미 있는 컴포넌트를 전제로 한다.

이후 화면 작업에서 여덟 모듈이 기능 PR 안에서 이슈 없이 추가됐다.

- `dialog`, `confirm-dialog`: Base UI Dialog를 감싼 껍데기(ADR-0015)
- `date-time-field`: 네이티브 `datetime-local` 래퍼(ADR-0016)
- `data-table`, `pagination`: 목록 화면의 표와 페이지 번호(ADR-0013)
- `link-notice`, `logo`, `spinner`: 화면 시안에 한 번씩 나오는 조각

이 모듈들은 Figma 컴포넌트 페이지에 표가 없고 화면 시안에서 모양이 한 번 정해지는 조립물이라 변형 표에 채울 값이 없다. 규칙과 실제가 어긋난 채로 두면 지켜지지 않는 문장이 하나 남는다.

비교한 선택지는 다음과 같다.

- 규칙을 모든 `shared/ui` 모듈에 유지: 기록이 한 형식으로 모이지만, 축이 하나도 없는 모듈에 빈 표를 만들고 화면 작업을 이슈 둘로 쪼개게 된다.
- 적용 범위를 Figma 컴포넌트 페이지에서 온 컴포넌트로 좁히기: 표가 있는 곳에만 표를 요구한다. 대신 조립 모듈의 요구 출처가 이슈가 아니라 화면 시안과 코드로 나뉜다.
- 규칙을 없애기: 이슈 형식이 단순해지지만 Button처럼 축이 셋인 컴포넌트의 요구를 저장소 어디에서도 볼 수 없다.

## Decision

- 변형 표를 담은 컴포넌트 이슈는 Figma 컴포넌트 페이지에 변형 축과 값이 표로 있는 `shared/ui` 컴포넌트에만 요구한다. ADR-0009의 적용 범위를 이 조건으로 좁힌다.
- 그 밖의 `shared/ui` 모듈은 별도 이슈 없이 그 모듈을 처음 쓰는 화면 이슈 안에서 만든다. 모양이 시안 한 곳에서 정해져 이슈에 옮길 표가 없기 때문이다.
- 조립 모듈의 기록은 `<이름>-variants.ts`의 `cva()` 정의와 테스트다. 변형 축이 없는 모듈은 테스트 이름이 역할, 상태, 슬롯을 문장으로 남긴다.
- 조립 모듈에 축이 생기면 그때 변형 표를 이슈로 만든다. Figma에 표가 없으면 그 축을 요구한 두 시안에서 읽은 값으로 채운다.

## Consequences

**좋은 점**

- 표가 있는 컴포넌트에만 표를 요구해 규칙과 실제가 같아지고, 화면 하나를 만드는 일이 이슈 둘로 갈라지지 않는다.
- Figma 컴포넌트의 변형은 여전히 이슈의 표로 먼저 확정되어 구현 전에 값이 정해진다.

**나쁜 점과 감수하는 위험**

- 조립 모듈의 요구가 저장소에 남지 않고 화면 시안에 있다. `cva()` 정의와 테스트 이름이 현재 모양을 남기는 것으로 대신한다.
- 어떤 모듈이 Figma 컴포넌트 페이지에서 왔는지는 사람이 판단한다. 판단이 갈리면 표를 만드는 쪽을 고른다.
- 다시 볼 조건: 조립 모듈이 여러 화면에서 서로 다른 모양을 요구해 변형 축을 갖기 시작하면 변형 표 요구를 그 모듈까지 넓힌다.
