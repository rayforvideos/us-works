# ADR-0002: Adopt Feature-Sliced Design Directory Structure

## Status

Accepted

## Context

ADR-0001에서 React + Vite 기반 SPA를 결정했다. 과제에는 폼, 어드민, 대시보드 형태의 화면이 여러 개 있을 수 있어, 화면 간에 공유되는 UI와 도메인 로직이 생긴다. 디렉토리 구조를 미리 정하지 않으면 컴포넌트, 훅, 아톰, API 호출이 한 폴더에 쌓이거나 의존 방향이 뒤엉켜 평가자가 코드를 따라가기 어려워진다.


널리 알려진 표준을 따르면 평가자가 별도 설명 없이 구조를 이해할 수 있고, 지원자가 아키텍처 기준을 갖고 있음을 보여줄 수 있다.

## Decision

- 디렉토리 구조로 Feature-Sliced Design(FSD) 2.1을 채택한다.
- `src/` 아래에 다음 여섯 레이어를 둔다. 위가 상위 레이어이며, 각 레이어는 자신보다 아래 레이어만 import한다.
  - `app`: 앱 초기화. 프로바이더(TanStack Query, Jotai), 라우터, 전역 스타일
  - `pages`: 라우트 단위 화면 조합
  - `widgets`: 독립적으로 동작하는 큰 UI 블록(헤더, 사이드바, 대시보드 카드 그룹)
  - `features`: 사용자 행위 단위 기능(필터 적용, 폼 제출, 로그인)
  - `entities`: 비즈니스 엔티티(user, order 등)의 타입, API, 표시용 UI
  - `shared`: 도메인 지식이 없는 재사용 코드(UI 원자 컴포넌트, API 클라이언트, 유틸, 설정)
- `pages`, `widgets`, `features`, `entities` 레이어는 도메인 단위 폴더인 슬라이스로 나누고, 같은 레이어의 슬라이스끼리는 import하지 않는다.
- 각 슬라이스 내부는 다음 세그먼트로 나누되 필요한 것만 만든다.
  - `ui`: 컴포넌트
  - `model`: Jotai 아톰, 스키마, 타입
  - `api`: TanStack Query 훅과 요청 함수
  - `lib`: 슬라이스 전용 유틸
  - `config`: 상수
- 모든 슬라이스는 `index.ts`를 공개 API로 두고, 외부에서는 이 파일을 통해서만 import한다. 슬라이스 내부 파일 경로를 직접 import하지 않는다.
- Jotai 아톰은 해당 슬라이스의 `model` 세그먼트에 둔다. 여러 기능이 공유하는 도메인 상태는 `entities/<엔티티>/model`에 두고, `shared`에는 도메인 상태를 두지 않는다.
- 경로 별칭 `@/*`를 `src/*`에 매핑하고, 레이어 간 import는 항상 별칭 절대 경로를 사용한다.
- FSD 2.1에서 폐기된 `processes` 레이어는 사용하지 않는다.
- 레이어 import 규칙은 문서화된 컨벤션으로 시작한다. 위반이 잦아지면 FSD 공식 린터 steiger나 ESLint import 규칙 도입을 별도 ADR로 결정한다.

## Consequences

**좋은 점**

- 의존 방향이 한 방향으로 고정되어 순환 참조가 구조적으로 막힌다.
- 코드가 어디에 있어야 하는지에 대한 판단 기준이 레이어 정의로 정해져, 파일 배치 고민이 줄어든다.
- 슬라이스 공개 API 덕분에 내부 구현을 바꿔도 다른 슬라이스에 영향이 없다.
- 널리 알려진 표준이라 평가자가 구조를 바로 이해할 수 있고, 아키텍처 기준을 보여줄 수 있다.
- Jotai 아톰과 TanStack Query 훅의 위치(`model`, `api`)가 정해져 상태 흐름을 추적하기 쉽다.

**나쁜 점과 감수하는 위험**

- 과제 규모에 비해 폴더 깊이가 깊어지고, 초기에는 비어 있는 레이어가 생길 수 있다. 필요한 슬라이스와 세그먼트만 만들어 완화한다.
- 슬라이스마다 `index.ts`를 관리하는 보일러플레이트가 늘어난다.
- 어떤 코드가 feature인지 widget인지 entity인지 판단이 필요하며, 초기에 잘못 놓으면 이동 비용이 든다. 판단 기준은 FSD 공식 문서의 정의를 따르고 애매하면 더 낮은 레이어에 둔다.
- 레이어 규칙을 도구로 강제하지 않는 동안은 위반이 코드 리뷰나 자체 점검에 의존한다.
- `docs/INITIALIZE.md`의 디렉토리 구조 설명을 이 결정에 맞게 개정해야 한다.
