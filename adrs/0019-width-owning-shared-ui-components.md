# ADR-0019: Let shared/ui Components Own Width When Width Is Their Spec

## Status

Accepted

## Context

ADR-0011은 `shared/ui` 컴포넌트가 브레이크포인트 클래스를 쓰지 않고 고정 `w-*`는 아이콘과 컨트롤 크기에만 쓴다고 정했다. 지금 코드에는 그 문장을 지키지 않는 자리가 셋 있다.

- `container`: 같은 ADR이 정한 공용 컨테이너가 `px-9 xl:px-25`로 브레이크포인트를 쓴다.
- `dialog`: Figma 시안이 팝업 폭을 484로 지정해 껍데기가 `w-121`(좁은 형태 `w-90`)을 갖는다(ADR-0015).
- `data-table`: 열이 눌리지 않도록 `min-w-160`을 갖고 컨테이너 안에서 가로 스크롤한다(ADR-0013).

세 모듈 모두 폭이 그 컴포넌트의 사양이라 부모가 정할 수 없다. 규칙은 한 줄인데 어긋나는 자리가 셋이므로 범위를 다시 그린다.

비교한 선택지는 다음과 같다.

- 규칙을 그대로 두고 세 모듈의 폭을 소비자로 옮기기: 규칙 문장은 지켜지지만 같은 폭 클래스를 쓰는 화면마다 반복하고, 다이얼로그 폭이 시안과 어긋나도 한 곳에서 잡히지 않는다.
- 폭이 사양인 컴포넌트만 예외로 인정하기: 규칙이 한 줄 늘지만 각 모듈의 폭이 그 모듈 안에 남는다.
- 규칙을 없애기: 판단 비용이 사라지지만 입력과 버튼까지 폭을 갖기 시작해 화면이 열 배치를 통제하지 못한다.

## Decision

- `shared/ui` 컴포넌트는 부모가 폭을 정하는 것을 기본으로 두되, 폭이 그 컴포넌트의 사양이면 스스로 고정 폭과 브레이크포인트 클래스를 갖는다. ADR-0011의 해당 항목을 이 범위로 좁힌다.
- 폭이 사양인 경우는 화면 폭을 나누는 컨테이너, 시안이 폭을 지정한 오버레이, 좁아지면 열이 무너지는 표다. 나머지 컴포넌트는 입력의 `w-full`, 버튼의 `fullWidth`, 아이콘과 컨트롤의 고정 크기만 갖는다.
- 폭 값은 `<이름>-variants.ts`의 `cva()` 안에 두고 소비자가 `className`으로 덮어쓸 수 있게 `cn`으로 마지막에 병합한다(ADR-0007).
- 반응형 판단은 위젯과 페이지가 한다. 컴포넌트의 브레이크포인트는 자기 폭과 여백에만 쓰고 내부 배치를 바꾸는 데는 쓰지 않는다.

## Consequences

**좋은 점**

- 시안이 정한 폭이 컴포넌트 한 곳에 남아 화면마다 반복되지 않고, 고치는 자리가 하나다.
- 문서와 코드가 같아져 `shared/ui`를 고칠 때 예외를 따로 기억하지 않는다.

**나쁜 점과 감수하는 위험**

- 폭이 사양인지 아닌지는 사람이 판단하고 도구가 막지 못한다. 판단이 갈리면 부모가 정하는 쪽을 고른다.
- 다시 볼 조건: 폭을 스스로 가진 컴포넌트가 셋을 넘어 화면이 열 배치를 통제하지 못하면 예외 범위를 다시 좁힌다.
