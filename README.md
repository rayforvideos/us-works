# us-works

Us FE Developer Recruit Works 과제 저장소입니다. 콘텐츠와 알람을 만들고 발행하는 SPA이며, React 19와 Vite 8 위에 Feature-Sliced Design 2.1 구조로 작성했습니다.

## 시작하기

필요한 버전은 Node 24(`.nvmrc`)와 pnpm 12.4.2입니다. pnpm은 `corepack enable`로 준비하실 수 있습니다.

```bash
pnpm install
```

메일에 첨부한 `.env.development`를 저장소 루트에 두고 실행해 주세요. 환경 변수 파일은 저장소에 커밋하지 않습니다.

```bash
pnpm dev       # 개발 서버, http://localhost:5173
pnpm build     # 타입 검사와 프로덕션 빌드
pnpm preview   # 빌드 결과 확인
```

계정은 화면에서 회원가입으로 만드실 수 있습니다.

## 검증

| 명령               | 하는 일                                                  |
| ------------------ | -------------------------------------------------------- |
| `pnpm check`       | typecheck, lint, knip, 포맷 검사, 테스트를 순서대로 실행 |
| `pnpm typecheck`   | `tsc -b`                                                 |
| `pnpm lint`        | ESLint(경고 0)와 steiger의 FSD 경계 검사                 |
| `pnpm lint:unused` | knip으로 쓰이지 않는 파일과 export 검사                  |
| `pnpm test:run`    | Vitest 단발 실행                                         |

현재 93개 파일에 566개 테스트가 있고 모두 통과합니다. 커밋 전에는 스테이징된 파일만 린트와 포맷을 돌리고, 푸시 전에는 `pnpm check` 전체가 돕니다. GitHub Actions는 PR마다 `pnpm check`와 `pnpm build`를 돌립니다.

## 구현 범위

| 경로            | 화면                                            |
| --------------- | ----------------------------------------------- |
| `/login`        | 로그인                                          |
| `/register`     | 회원가입                                        |
| `/`             | 콘텐츠 목록. 카테고리와 상태 필터, 페이지네이션 |
| `/alarms`       | 알람 목록                                       |
| `/contents/new` | 콘텐츠 작성. 임시저장과 30초 자동 저장          |
| `/contents/:id` | 콘텐츠 수정                                     |
| `/alarms/new`   | 알람 작성. 콘텐츠를 지정해 들어옵니다           |
| `/alarms/:id`   | 알람 수정                                       |

발행은 별도 모달에서 공개 여부와 예약 시각, 알람 설정을 함께 정합니다. 목표 상태와 현재 상태의 차이만 요청으로 만들어 순서대로 보냅니다.

상태를 두는 자리는 셋으로 나눴습니다. 목록의 페이지와 필터는 URL에, 서버 데이터는 TanStack Query 캐시에, 세션은 Jotai 아톰과 로컬 스토리지에 둡니다. 작성 중인 콘텐츠는 로컬 스토리지에 임시저장합니다.

인증은 access token을 메모리에, refresh token을 로컬 스토리지에 둡니다. 요청 직전에 만료를 확인해 필요하면 먼저 갱신하고, 401을 받으면 한 번만 갱신 후 재시도합니다. 갱신은 동시에 하나만 돌고, 실패하면 세션과 쿼리 캐시를 함께 비운 뒤 로그인 화면으로 보냅니다.

## 주요 결정

결정의 배경과 비교한 선택지는 `adrs/`에 있습니다. 읽는 순서를 줄이시도록 핵심만 추렸습니다.

- 레이어와 슬라이스 경계를 도구로 강제합니다. 사람이 지키는 규칙이 아니라 eslint-plugin-boundaries와 steiger가 막습니다(ADR-0002, ADR-0003).
- 목록의 페이지와 필터를 URL에 둡니다. 행을 눌러 다른 화면에 갔다가 돌아와도 위치가 복원되기 때문에 무한 스크롤 대신 번호 페이지네이션을 골랐습니다(ADR-0013).
- 인증은 HTTP 클라이언트가 처리기를 주입받아 한 곳에서 처리합니다. 요청 직전 만료 확인, 401 후 한 번의 재시도, 동시 요청의 단일 갱신이 모두 인터셉터 안에 있습니다(ADR-0006, ADR-0020).
- 조회의 쿼리 키와 옵션을 엔티티의 팩토리 한 곳에 모읍니다. 키가 흩어져 무효화가 빠지는 문제를 겪고 바꾼 결정입니다(ADR-0021).
- 작성 중인 콘텐츠는 로컬 스토리지에 임시저장합니다. 서버에 초안 API가 없어 새로고침과 이탈에 대비했습니다(ADR-0014).

## 작업 방식

초기 셋업은 `main`에서 바로 진행했습니다. 스캐폴딩과 기본 규칙, 린트와 CI 설정까지 커밋 21개가 여기 해당합니다. 그 뒤로는 모든 변경을 GitHub Issue에서 시작해 `<이슈번호>-<짧은-영문-설명>` 브랜치에서 작업하고, `main`으로 PR을 올려 CI 통과 후 merge commit으로 합쳤습니다. 이슈 55건과 PR 54건이 이 흐름을 지났습니다.

기록은 세 곳으로 나눴습니다.

- `adrs/`: 왜 그렇게 했는지 남깁니다. 22건이며 각각 Status, Context, Decision, Consequences 네 절만 씁니다. 비교한 선택지와 다시 볼 조건을 함께 적었습니다.
- `specs/`: 화면이 약속한 것을 남깁니다. 9건이며 규칙(`R-xx`)과 흐름(`S-xx`) 문장에 ID를 붙이고, 그 문장을 테스트 이름에 그대로 씁니다.
- `docs/`: 구현 규칙을 남깁니다. API 연동, 코드 품질, 파일 구조, 테스트, 공용 컴포넌트, 미룬 리팩토링 여섯 가지입니다.

테스트는 모듈이 약속한 것 하나가 테스트 하나입니다. 순수 로직은 구현 전에 쓰고, 화면은 사양 문장을 구현하면서 씁니다. 클래스 문자열은 검사하지 않고 역할과 이름으로 찾습니다.

## 구조

```
src/
├── app/        # 진입점, 프로바이더, 라우트, 전역 스타일
├── pages/      # 라우트 단위 화면
├── widgets/    # 화면 지식이 없는 큰 UI 블록
├── features/   # 사용자 행위 단위 기능
├── entities/   # 비즈니스 엔티티와 요청 함수, 쿼리 팩토리
└── shared/     # 도메인 지식이 없는 재사용 코드
```

레이어 순서와 슬라이스 간 참조 금지는 eslint-plugin-boundaries와 steiger가 강제합니다. 위반은 린트 실패입니다.

## 기술 선택

React 19.3과 React Compiler, TypeScript, Vite 8, Tailwind CSS 4, TanStack Query 5, TanStack Form 1.33, Jotai 3, React Router 8, zod 4, Base UI를 썼습니다. 각 선택의 이유는 `adrs/0001-tech-stack.md`에 있습니다.
